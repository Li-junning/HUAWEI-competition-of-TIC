# 自建证据知识库

这是可信度验证台自己的 RAG 知识库。资料正文、出处、日期、分类、文本片段和向量都保存在现有 SQLite 数据库中，不需要另起数据库服务。网页检索与知识库检索共用现有逐条证据判断流程。

## 使用

1. 重启后端，并打开页面右上角的“我的知识库”。
2. 填写标题，上传 Word（`.docx`）、TXT、Markdown、可提取文字的 PDF，或粘贴正文。建议同时填写发布方、原始出处、发布日期和分类标签。
3. 点击“保存到我的知识库”，在“试搜知识库”中检查片段是否正确。
4. 返回可信度验证，提交一段 AI 回答。新任务和声明重试会自动检索本地资料，联网搜索按原有配置执行。
5. 在声明详情中点击“定位知识库原文”，查看对应页码、原文高亮和资料版本。

网页出处链接只作为元数据保存，导入接口不会根据链接抓取网页。需要纳入网站资料时，先取得正文，再粘贴或上传；系统已有的 Tavily 检索仍可提供联网候选。

### Word 文档

Word（`.docx`）可直接选择或拖拽导入，提取正文段落和表格中的文字，并按文档顺序保存。表格行以换行分隔，单元格以制表符分隔，合并单元格文字保留一次；嵌套表格也提取文字。导入后可检索、定位原文片段和记录资料版本。字号、排版、图片、页眉页脚、批注和修订记录不作为正文提取；图片中的文字需要先进行 OCR。

Word 的视觉分页依赖排版环境，提取正文按单份连续文本保存，不生成视觉页码。旧版 `.doc` 请在 Word 中选择“另存为”并保存为 `.docx`；仅修改文件扩展名不能转换格式。加密或损坏的文件会明确报错。

更新到本版本后，在 backend 目录执行 `.\.venv\Scripts\python.exe -m pip install -e ".[dev,knowledge]"` 并重启后端；基础依赖包含 `python-docx`，不要求安装或打开 Microsoft Word。

### 出现 404 或“后端未加载知识库接口”

表示当前运行的后端没有知识库路由，常见原因是前端已加载新代码，8000 端口的后端仍运行更新前的进程。关闭旧后端窗口，再运行 `启动整个程序.bat` 并刷新页面。启动脚本会同时检查知识库接口，发现旧后端时给出明确提示；仅重复双击不会自动重启已运行的后端。404 不是请求超时，也不是资料正文有问题。

## 本地向量模型

中文语义检索采用 `BAAI/bge-small-zh-v1.5`，CPU 运行，512 维向量。关键词通道使用 FTS5 BM25，对中文先做双字分词；两个通道通过 RRF 排序合并。RRF 分数只用于检索排序，不进入事实可信度评分。

语义候选使用 0.50 的初始相似度门槛，它是检索启发式，尚未经过领域数据集校准；后续应根据真实资料的人工案例调整和评测。候选仍须经过逐项证据判断。

首次安装或更换电脑，在 **backend 目录**执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,knowledge]"
.\.venv\Scripts\python.exe scripts\prepare_knowledge_model.py
```

模型准备脚本只下载模型权重，不上传知识库资料。运行完成后重启后端。正常 API 请求只加载本机缓存，不下载模型；未准备模型、关闭语义检索或向量生成失败时，正文与关键词索引保留，页面明确显示关键词模式或降级原因。已有资料没有向量时可点击“补建语义索引”，每次最多处理 200 个片段。

配置项：

- `VERIFIER_KB_EMBEDDINGS=auto`：默认，仅使用已缓存的模型；`off` 关闭向量通道。
- `VERIFIER_KB_MODEL=BAAI/bge-small-zh-v1.5`：准备脚本和后端必须使用同一模型。更换模型后重启并补建索引；不同模型的向量不混用。
- `VERIFIER_KB_CACHE_DIR`：可选缓存位置；默认位于数据库目录下的 `knowledge-models`。

第一版适合个人资料库：最多 200 份资料、5,000 个片段；向量与原文一起存入 SQLite，语义查询进行有限规模的向量比较。需要显著扩大容量时再迁移到 Qdrant 等向量服务，导入、片段定位和证据判断契约可复用。

## 可复核规则

- 资料分成不超过 420 字符、相邻重叠约 60 字符的原文片段，避免长中文段落在模型输入端被大量截断。
- PDF 保留页码；位置是该页提取文字中的 Unicode 字符半开区间 `[start, end)`，不是浏览器 UTF-16 位置或 PDF 视觉坐标。前端按 Unicode 字符定位高亮。
- Word 正文与表格按提取顺序合并为单份文本；检索片段页码为 `null`，字符位置对应保存的提取正文。
- 资料正文按提取后内容保存；文本换行规范化为 LF。SHA-256 标识完整提取正文版本。完全相同的正文拒绝重复导入。
- 上传是收录资料，不是认证来源。上传者填写的地址不会自动获得政府或高校来源的高信任权重，本地资料采用保守来源权重。
- 同一站点、相同正文、重复片段以及已有证据簇合并；没有外部出处的本地资料合并为一个来源，不能靠重复上传增加独立来源数。
- 检索同时保留原声明和不预设答案的查询，以便寻找反驳材料；判断仍需核对主体、属性、时间、范围、数值与原文引用。语义相似度不代表支持关系。
- 关闭模型判断时仍可检索并展示资料，但命中不会直接产生“可信”结论。模型判断开启时，命中的片段会按现有流程发送给配置的判断服务。
- 网页搜索失败而本地证据可用时，保留本地证据并显示检索警告；任务记为部分完成，总体指数继续受到技术失败门槛约束。
- 删除资料同时删除其检索索引，只影响后续检索。历史任务保留证据片段、位置和版本哈希；资料删除后无法通过管理页打开完整正文。
- 不支持扫描 PDF 的 OCR、自动网站同步、文件附件中的图片或表格视觉解析。单文件最多 2 MiB、PDF 最多 100 页、正文最多 100,000 字符，超限明确拒绝而不静默截断。

## 第一批资料怎么准备

先选择一个明确领域，导入你能核对出处的原始资料。保留时间、适用范围、修订版本，区分论文结论与个人笔记。为每批资料整理“直接支持、直接反驳、资料未覆盖、时间范围不一致”四类人工案例，核对检索和判断结果；不要把合成测试材料混入实际证据库。

## 验证

```powershell
# backend 目录；临时数据库放在项目数据目录，不访问实际资料库。
.\.venv\Scripts\python.exe -m pytest -q --basetemp=data/knowledge-tests
```

`tests/test_knowledge.py` 覆盖资料导入/删除、重启持久化、完整正文定位、PDF 页码、中文关键词和分类过滤、冲突答案保留、向量通道与补建索引、向量失败降级、恶意 URL/文件输入拒绝、知识库请求体限制、历史证据快照和网页失败语义。`tests/test_word_import.py` 覆盖 Word 正文与表格顺序、合并及嵌套单元格、检索与位置、重启持久化、文件损坏和资源上限。语义通道单元测试使用概念向量夹具，不能据此声称真实检索准确率。

准备好模型后，还可以运行 `.\.venv\Scripts\python.exe scripts\check_knowledge_retrieval.py`。它使用独立测试数据库检查真实模型对两种无共同关键词表达的检索、无关查询和原文位置，报告保存到 `data/knowledge-smoke/report.json`。这仍是合成冒烟检查，不是领域准确率评估。
