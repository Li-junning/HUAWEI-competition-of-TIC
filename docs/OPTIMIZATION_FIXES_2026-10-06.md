## 修改后的行为

| 问题 | 修复 |
| --- | --- |
| 自填网址可制造独立来源 | 上传资料保留检索、原文定位和逐项核对，但出处未核实，不参与裁决强度或支持指数；不同自填域名不再增加独立性 |

| 融合丢失复合声明事实 | 在证据数量上限内先保留覆盖各事实的候选，再增加来源多样性；同站多页仍不重复计独立性 |
| 长回答逐条串行 | 默认最多三条声明并发；所有任务共享搜索槽位，排队计入截止时间，模型判断保留原有共享限流，并预留判断时间 |
| 超时的未处理声明不能恢复 | 新增 unchecked_reason，预算耗尽显示“继续核验”；历史预算说明也可恢复，指代不明仍需先人工澄清 |
| 意见词跳过事实 | “值得注意的是”“推荐免试”“推荐系统”“建议书”等不再凭关键词排除事实；明确建议与主观评价仍为不适用；保留原文及 UTF-16 区间 |
| 单条指数缺失 | 保存声明时计算指数，旧报告读取时按同一规则派生；列表、详情、摘要和导出保持一致 |
| 查询数配置未生效 | VERIFIER_MAX_QUERIES 实际限制本地与网页的共同计划，也限制注入的内置检索器；范围 1–3，默认 3 |

## 使用

关闭旧后端窗口后重新启动程序，再刷新页面。已运行的启动脚本会复用服务，仅重复双击不一定重启旧后端。

`.env.example` 已列出 VERIFIER_MAX_QUERIES 和并发说明。无需改变配置即可使用默认的三条并发、每条最多三组查询；修改环境变量后需重启后端。

新任务采用以上行为。旧报告的标签和证据不会自动重新检索或重判；缺失的单条指数会在读取时派生。已保存的预算耗尽声明可继续核验；历史观点误分类需要新建任务，或通过人工复核调整后重新核验。

上传出处目前没有自动认证接口，上传资料只能作为参考。需要可裁决的网页证据时，由已配置的搜索供应商获取，再执行原有主体、属性、范围、答案和原文引用校验。
