# 运行与复核可靠性优化

2026-09-30 对任务恢复、人工复核和前端请求处理进行了针对性优化。

## 服务重启后的恢复

服务启动时，在同一数据库事务中将未结束的任务标为 `interrupted`，并将其仍处于等待、抽取、检索或判断阶段的声明标为技术失败。声明提示服务中断，可以使用原有“重新检索”按钮继续核验；已经完成的结果和已保存的证据保持可查看。

中断不构成反证，活动声明不会保留可误读为完成结论的标签或支持指数。成功恢复到 `succeeded` 的任务会清除旧任务错误码。尚未抽取任何声明的任务仍需重新提交原文。

## 人工复核反馈

人工修改、拆分、合并、补充和撤销的写入与结果刷新分别处理。后端已保存操作、后续读取失败时，页面明确提示操作已保存、应刷新结果，不应重复提交；读取成功的结果仍会更新。

保存期间禁用重复编辑和重新检索。切换任务后，旧请求不能覆盖新任务的提示、操作记录或保存状态。辅助的操作记录加载失败也不会遮住更重要的声明加载错误。

## API 请求与导出

JSON 请求和报告导出使用有时限的请求处理，超时覆盖响应正文读取。无效 JSON 和异常错误响应给出可恢复的 API 错误；删除声明返回的合法 `204` 响应仍视为成功。写操作不会自动重试，避免重复创建任务或重复提交复核。

跨域配置增加现有人工编辑、删除功能需要的 `PATCH` 和 `DELETE` 方法，允许来源仍由现有配置控制。

## 验证方式

使用临时数据库、模拟网络与供应商运行回归测试，不读取用户任务数据库，不调用真实搜索或模型服务。新增测试覆盖中断恢复、事务回滚、错误码清理、旧请求隔离、保存后的读取失败、异常响应、导出超时和浏览器跨域预检。

本次最终验证：后端 414 项测试、前端 71 项测试全部通过；前端类型检查与生产构建通过；现有 8 条合成夹具的离线评估通过，功能约束无失败。后端仅有原有的两项测试依赖弃用警告。

在某些 Windows 环境中，已有的系统临时目录可能归其他用户所有。可为 pytest 使用项目内独立目录：

```powershell
cd backend
New-Item -ItemType Directory -Path .pytest-runtime -Force | Out-Null
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.pytest-runtime/verification -o cache_dir=.pytest-runtime/cache
```

前端检查保持原命令：

```powershell
cd frontend
npm run typecheck
npm test
npm run build
```

既有合成夹具离线评估可验证核验与评分约束，但不代表真实联网核验准确率。后端代码修改需要重启后端服务后生效。
