# 网页证据与声明比对

2026-09-30 的调整针对“引用真实，但不证明待核验声明”的误判。检索流程与 API 字段保持兼容；模型仍在一次判断请求内处理已保存的证据，不自行联网。以下检查只能降低不充分判断的可信程度，不会根据关键词自动纠正事实。

## 逐项核对

每条证据都需针对待核验声明的每个 `part_id` 返回 `checks`。每项包含关系、连续原文引用，以及四个 `alignment` 维度：

| 维度 | 含义 | 可用值 |
| --- | --- | --- |
| `entity` | 同一主体身份，区分同名对象、附属单位和主体 | `match / mismatch / unknown` |
| `predicate` | 同一动作、属性或统计指标 | `match / mismatch / unknown` |
| `scope` | 同一时间、条件、口径、地域层级与量词 | `match / mismatch / unknown` |
| `value` | 支持答案、互斥答案，或无法确认 | `match / conflict / unknown` |

直接支持要求四维都为 `match`。直接反驳要求前三维为 `match`、答案为 `conflict`。信息未出现、范围不同、条件未确认不能成为直接反证。标题和发布日期只作为元数据：标题不能替代正文，页面发布日不能替代事实发生日期或自动证明时效。

程序先检查证据 ID 和引用原文，再核对各维度及本地约束，最后由核对项汇总整句关系。任一有效直接反证可反驳整句；全部核对项有效支持才是整句支持；部分支持不计入直接支持分数。模型的整句关系不能覆盖核对项中的反证。重复或越界的核对项 ID、重复证据 ID 均拒绝采纳；缺失的决定会清空旧关系和相关性分数。

旧格式缺少 `alignment` 时，只允许通过上下文检查的完整逐字支持，或可识别主体属性的明确否定。旧的复合支持但缺少逐项检查仍降为部分支持，不能决定整句可信。

## 本地上下文检查

`backend/app/evidence_alignment.py` 将模型引用定位回保存文本的完整句子。相同引用多次出现时，所有位置都需通过检查，不能只选择有利的一次。正文仍保留，供页面复核。

- 检查被引用片段前后的否定、条件、推测与转述，防止引用截去“不能”“如果”“据称”等限制。
- 对可识别的地点、成立、出生、毕业等属性，把引用绑定到直接描述该属性的主体。不能从其他句子借主体，不能把附属医院的地址代替大学地址，也不能把就读当成毕业。
- 对可识别的日期核对精度：更具体的同年日期可以支持年份；只有年份不能证明具体月份。属性值日期与观察时间分开处理；不同年份的指标不能直接比较。
- 对常见金额、长度、质量、速度、人数、百分比和摄氏温度使用精确有理数换算，避免浮点误差。同一数字但不同单位不等价；人民币与美元不自动换算。研发投入、营收等指标的数据必须与被引用指标绑定。
- 相同属性答案或包含关系不能单独反驳；仅相关事实不能证明因果；部分个体不能直接支持全称声明。

失败原因写入现有 `quality_reason`，可在证据详情中复核；不复制未经验证的模型自由理由。证据不足继续不计分，同站转载的独立性规则继续适用。

## 验证与限制

新增回归用例见 `backend/tests/test_evidence_alignment.py`，覆盖伪支持、伪反证、有效支持、直接反证、复合冲突、缺项、重复 ID、虚构引用及旧分数清理。用例通过模拟模型返回刻意错误的关系和“全部匹配”维度，检查本地约束是否能够阻止错误裁决；不调用真实 API。

本轮新增 78 项回归用例，完整后端 401 项测试通过；现有离线合成评估的分类及功能约束检查通过。验证结果只说明这些已知用例和程序流程通过，不代表已经测得真实联网准确率。

这些规则不是通用语言理解器。复杂别名、跨句省略、日期表达、地点层级、比较/近似值、统计口径和因果关系仍依赖模型语义判断，且更保守的检查可能增加弃判。规则不推断网页是否真实或当前仍有效，结构化维度也不是事实真实性保证。真实联网准确率仍需人工标注样本盲测，不能由单元测试通过率推算。

修改后需重启后端并新建任务，或重新检索相关声明，才会使用新的比对逻辑。历史结果不会自动改写。
