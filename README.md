# AI 答案可信度验证系统

这是一个面向比赛演示的最小可行实现：用户粘贴一段 AI 回答，系统抽取最多 15 条可核验声明，收集并聚类证据，保守地给出“可信 / 存在争议 / 错误 / 证据不足 / 不适用”结论，同时公开覆盖率、失败来源和未处理声明。

项目的首要原则是“可复核，不装懂”：技术失败不得伪装成反证，证据不足不得计入总分，达到声明上限必须明确提示截断。

## 目录

```text
backend/       FastAPI、SQLite、验证流水线与供应商适配器
frontend/      Vue 3 + TypeScript 单页应用
contracts/     前后端共享的 API 契约说明
docs/          架构、安全模型与开发约束
evaluation/    可公开的冒烟评估样本
```

## 开发原则

- 默认启用 mock provider，未配置任何外部密钥时也应能完成端到端演示。
- 外部网页、搜索结果和模型输出一律视为不可信输入。
- API 密钥仅从后端环境变量读取，前端构建产物和日志不得包含密钥。
- 仅抓取 `http` / `https`，并在 DNS 解析与每次重定向后执行 SSRF 检查。
- 所有外部调用有超时、大小、并发、重试和总预算限制。
- SQLite 只保存必要数据；日志默认不记录完整用户原文或网页正文。

具体契约见 [contracts/api.md](contracts/api.md)，安全边界见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

程序按“应用初始化 → HTTP 路由 → 核验流水线 → 供应商/存储”分层；前端按“页面展示 → 任务与筛选状态 → API 客户端”分层。目录与重构记录见 [docs/REFACTOR.md](docs/REFACTOR.md)。

断句、检索词规范化、正文摘录与网页排序规则及验收方法见 [docs/RETRIEVAL_QUALITY.md](docs/RETRIEVAL_QUALITY.md)。

网页证据与声明的逐项匹配、主体/属性/范围/答案核对、上下文及数值单位校验见 [docs/EVIDENCE_ALIGNMENT.md](docs/EVIDENCE_ALIGNMENT.md)。引用出现在网页中只是第一道校验；不能证明整条声明的引用会保留为待确认或部分支持，具体原因显示在证据详情中。

## 本地启动

Windows 首次安装下方依赖并配置根目录 `.env` 后，可直接双击 `启动整个程序.bat`。脚本会打开后端与前端命令窗口，确认两者就绪后打开浏览器；重复运行会复用已经启动的服务。此脚本仅监听本机 `127.0.0.1`。

后端（PowerShell）：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

前端另开一个终端：

```powershell
cd frontend
npm install
npm run dev
```

打开 `http://localhost:5173` 即可使用。默认 provider 为 `mock`，不会访问互联网；未接入实时 provider 时，事实声明会保守地显示为“证据不足”。

如果通过局域网或公网提供服务，应由 HTTPS 反向代理同时提供前端和 `/api`，并限制可访问的来源；不要直接把 Vite 开发服务器作为公网服务。当前 API 没有登录或任务归属隔离：任何能连接服务的人都能创建任务，持有任务 ID 的人能读取结果。不要把 `.env` 或 `backend/data` 随项目打包发布。

如需明确启用联网搜索和模型判断，请将 `.env.example` 复制为项目根目录 `.env`，填写密钥并分别设置 `VERIFIER_PROVIDER_MODE=tavily`、`VERIFIER_JUDGE_MODE=mimo`，然后重启后端。服务不会覆盖已有进程环境变量，也不会执行 `.env` 内容；`GET /api/status` 和输入页会显示当前是否已启用。密钥缺失时保持离线/失败语义，不会自动寻找其他密钥。

## 任务恢复与证据复核

创建任务后，地址栏保存 `?task=<任务ID>`；进入声明详情时附带 `claim`。刷新页面或使用浏览器前进/后退可恢复相应任务，运行中的任务会继续刷新。旧的仅包含 `claim` 的链接也可恢复所属任务。链接只保存标识，不包含用户原文；原文从后端单独读取，用于精确高亮。当前服务没有任务所有权隔离，能连接服务并持有任务链接的人可以读取原文与结果。

短暂网络故障会触发有限的只读重试，创建任务和人工重试不会自动重复提交。停止刷新只暂停页面查询；新建任务会隔离旧请求，避免迟到的响应覆盖当前页面。

报告中的原文高亮可直接打开声明；详情页可展开原文定位，并在原有证据簇内按支持、部分支持、反驳和待确认分组。分组不会把转载或同一证据簇计算成多个独立来源。报告页可打印摘要，声明详情页可打印当前证据；完整可复核数据仍可导出 JSON 或 Markdown。

搜索摘要低于可核对的网页正文，但不再一律排除。经过证据片段校验并被判为直接支持或反驳的摘要，可以与其他独立来源交叉印证。部分支持不进入整句支持分数，不能靠来源数量填补尚未核验的事实。复合声明在判为支持前必须逐项返回可核对的证据片段；漏项、伪造引用或用其他属性的片段替代时降为部分支持。单条摘要、仅来自资质未确认网站的摘要，以及同一证据簇内的重复结果也不能单独决定结论。由摘要得出的结论会明确提示尚未取得可核对的网页全文；存在较强相反证据时保留为证据不足，双方都达到充分门槛时标为存在争议。

检索保留原声明查询，并为地点、入海口、成立时间、毕业院校等属性增加不带预设答案的查询；不同答案仍可作为反证候选。同一主体但没有目标属性的材料不能替代目标事实。旧的复合声明重新检索时，会在现有三次查询预算内优先覆盖各项事实。

任务完成后，点击报告页的“人工调整断句”进入独立复核页面；该页面可在原文中选区补充遗漏声明、指定位置拆分声明、合并相邻声明，并查看当前断句和操作记录。页面地址中的 `review=1` 可在刷新后恢复复核页面。声明卡片也可修改文字或删除。每次操作保存审核人署名、时间及修改前后文字；操作记录支持从最近一次开始撤销。人工调整后的声明会标记为未核验，需重新检索。审核人署名目前由用户自行填写，不能作为身份认证依据。

## 搜索调用故障排查

`/api/status` 表示适配器已配置，不代表已验证外部 API 连通性。搜索失败时，声明详情中的原因和后端日志会给出分类错误码；不会记录密钥或上游原始响应。

- `SEARCH_NETWORK_PERMISSION`：后端进程的联网被系统或沙箱限制（例如 Windows 的 `WinError 10013`）。在允许联网的本机 PowerShell 中按上面的命令启动后端；不要通过更换密钥或关闭证书校验处理此问题。
- `SEARCH_AUTH`：检查根目录 `.env` 中的 `SEARCH_API_KEY`，修改后重启后端。已有进程环境变量优先于 `.env`。
- `SEARCH_QUOTA` / `SEARCH_RATE_LIMIT`：分别检查 Tavily 使用额度，或等待限流解除。
  Tavily 对连接失败、超时和临时服务错误最多尝试 3 次；单次请求最多 20 秒，单条检索最多 60 秒，并受任务剩余预算限制。遇到限流时遵守服务端的 `Retry-After`，等待时间超过剩余预算就停止本次检索。
- `SEARCH_CONNECTION` / `SEARCH_TIMEOUT`：检查后端所在环境的网络、代理与证书设置。

前端代理默认连接后端 `8000` 端口。另起 `8001` 端口的后端不会自动改变前端连接目标。修复后提交新任务或在页面有限重试，旧任务保存的失败原因不会自动更新。

## 模型语义切分

原有本地自动断句按标点、换行分割，并保护小数、链接、缩写。现在可在根目录 `.env` 添加 `VERIFIER_SEGMENT_MODE=mimo`，复用现有 `MIMO_API_KEY`、`MIMO_BASE_URL`、`MIMO_MODEL`，重启后端生效。切分开关与模型判断独立；默认 `rules` 不为切分调用 API。

启用后会把输入全文发送给 MiMo，按独立事实分段，再检索和核验证据，会增加延迟及 token 费用。共享主语的并列动作允许分别核验：模型返回连续原文 `source` 和原文句首的共享前缀 `context`，组合成保留时间、范围与主语的 `normalized_claim`。原文片段及 UTF-16 高亮位置仍逐字对应，程序拒绝遗漏和编造上下文。条件、否定、因果等关系在其所属声明内完整保留；完整因果事实后的独立事实可以另行核验。明确的连续主语可用于还原“它、他、她”等代词；出现竞争对象、跨段落或指代不明时不猜测。跨句还原由本地原文校验处理，模型不能任意借用其他句子的上下文。

本地规则也会拆分能明确识别主语的常见并列动作，既用于离线模式，也用于细化模型返回的过粗整句。对于本地规则可确认的相同边界，模型上下文若误包含前一个事实，会裁回共同主语和限定信息。例如“甲公司发布A产品，并收购乙公司”会形成两条声明，第二条保留“甲公司”，不会重复“发布A产品”。这不是完整语法分析；复杂省略、跨句指代、未知谓语仍可能保持整句，需要人工标注评估实际精度。

切分含排队和重试最多 30 秒，并受任务剩余预算限制。超时、拒答、输出截断（长输入尤其可能发生）或校验失败时整次回退本地规则继续核验。页面摘要显示实际切分方式；日志 `segmentation_fallback` 记录错误码，不保存原文或密钥。超过声明上限时按实际切分数量报告未核验条数。服务状态表示配置方式，不代表 API 连通性已经验证。

## 模型调用故障排查

模型失败时，声明卡片会显示 `LLM_*` 错误码、可用的 HTTP 状态码和诊断编号。默认日志为 `backend/data/logs/providers.log`（随数据库目录变化），按 2 MiB 轮转并保留 3 份备份。搜索诊断编号可找到关联的任务、声明、每次请求耗时和返回结果类别；日志不保存密钥、提示词、证据正文或模型原始输出。

- `LLM_AUTH` / `LLM_FORBIDDEN` / `LLM_QUOTA` / `LLM_MODEL`：分别检查密钥、权限、额度、模型或接口地址。
- `LLM_TIMEOUT` / `LLM_CONNECTION` / `LLM_NETWORK_PERMISSION`：请求超时、连接失败或系统禁止联网。
- `LLM_CONTENT_FILTER`：服务返回了明确的内容拦截或拒答标志。
- `LLM_TRUNCATED`：模型输出达到长度上限，即使返回 HTTP 200 也不能作为完整判断使用。
- `LLM_REPETITION`：模型检测到重复生成而中止。
- `LLM_EMPTY` / `LLM_RESPONSE` / `LLM_JSON` / `LLM_SCHEMA`：分别表示输出为空、API 响应结构异常、模型输出不是有效 JSON、JSON 字段不符合判断约定。
- `LLM_INTERNAL`：后端判断程序内部异常。日志只保存异常类型与代码位置，不能将其误认为 API 密钥错误。

每次模型请求默认使用 60 秒总时间上限（包含等待响应头和读取完整响应），单条判断从排队开始，所有请求及退避合计默认最多 120 秒，并受任务剩余时间限制。超时会取消请求并关闭连接。模型判断与语义切分共用进程内最多 2 条并发调用，避免两种用途同时挤占 MiMo 接口。

超时、连接失败、限流和临时服务错误采用指数退避并加入少量随机等待，支持秒数与 HTTP 日期两种 `Retry-After`；若服务要求的等待超过剩余预算，会停止尝试，不会提前重试。所有失败类型合计最多 3 次尝试。空输出、JSON/字段格式错误、重复生成或截断最多重新生成 1 次；截断恢复时将输出额度从默认 1800 tokens 提高到最多 3600。仅去除完整包裹 JSON 的 Markdown 代码块，不补造不完整 JSON，不放宽证据 ID、引用原文及关系校验。

内容拦截、密钥、权限、额度错误立即停止；延长超时无法解决服务端内容拦截，检索证据会保留供人工核对。不会自动改用其他模型或将失败伪装成事实判断。日志中的 `llm_attempt` 和 `llm_retry` 会记录每次尝试的时间预算、输出额度和退避等待。

可在根目录 `.env` 调整 `MIMO_REQUEST_TIMEOUT_SECONDS`（默认 60，上限 90）、`MIMO_TOTAL_TIMEOUT_SECONDS`（默认 120，上限 180）、`MIMO_MAX_CONCURRENCY`（默认 2，上限 3）、`MIMO_MAX_COMPLETION_TOKENS`（默认 1800，上限 3600）。无需填写这些变量即可使用默认值；修改后重启后端或重新双击启动文件。历史任务中只有笼统错误的记录无法追溯具体原因，应以新诊断记录为准。

接受声明重试时，任务会先进入 `running` 状态，前端持续查询直到重试完成并刷新证据详情，避免立即展示上一次的失败结果。同一任务处理中不能再次提交重试。

## 验证

```powershell
cd backend
python -m pytest -q

cd ..\frontend
npm run typecheck
npm test
npm run build
```

联网搜索与模型判断已提供 Tavily/MiMo 适配器，并由环境变量显式选择；它们是否可用取决于对应真实密钥和外部服务连通性。启用 Tavily/MiMo 模式却未填写 `SEARCH_API_KEY` 或 `MIMO_API_KEY` 时，后端 provider 初始化可能失败；系统不会自动回退为离线结果，也不会伪造在线结果。接入或扩展 provider 时必须实现超时/重试/预算、调用审计，以及 `SafeHttpClient` 所要求的 DNS 固定传输；不得直接绕过安全客户端发起任意 URL 请求。
